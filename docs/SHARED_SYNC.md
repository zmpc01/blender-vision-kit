## What is shared

`tools/shared_manifest.json` governs **44 script files** shared
between this kit and downstream scene repos (today:
blender-escape-previz). Every entry has ONE canonical `owner`:

- `owner: "kit"` (42 files) — infra: `blender_kit/`, the gates/audits,
  the capture/vision tools, `apply_patch`, `scene_schema`,
  `physics_place`, `blrun.sh`, ...
- `owner: "previz"` (2 files) — scene-data-bearing:
  `ual_bake.py` (beat tables = choreography), `assets_ual_actors.py`
  (character/color tables)

Deliberately NOT governed: `export_previz_package.py` (previz's copy
is the frozen rollback fallback until the 3-green window closes, then
a shim — kit-only forever after), crowd code (session-27 law: loads
via `--crowd-plugin`, never vendored into the kit's namespace), and
each repo's private files (scene modules, escape_lib, crowd_v6, ...).

`tools/shared_audit.json` is the machine-generated both-repos
classification (identical / diverged / kit-only / previz-only) —
regenerated by every `--emit`.

## The law (AGENTS.md gotcha 114)

**Changes to a manifest file land in its OWNER repo first** (with a
regression test), then:

```bash
# in the kit (the ONLY place syncs run):
python3 tools/sync_shared.py --emit          # refresh the canonical manifest
python3 tools/sync_shared.py --to /home/z/blender-escape-previz   # vendor everywhere
```

`--to` = copy (per-entry owner→non-owner) → re-emit → vendor the
record + checker → check. For `owner: previz` entries it pulls
previz→kit (bidirectional per entry; the report shows the arrows).

**Emergency hotfix in the non-owner repo**: fix there, then port back
to the owner THE SAME SESSION. The enforcement surfaces make a
forgotten port-back visible:

| Surface | Where | Behavior |
|---|---|---|
| Kit test | `tests/test_shared_manifest.py` (S1-S5) | BLOCKING (sha match, closure, scope-law, consumer IN-SYNC) |
| Previz dev gate | `scripts/dry_gates_s30.py` | exit 1 on NON-OWNER-AHEAD/DIVERGED (`ALLOW_DRIFT=1` escape) |
| Production export | step8 pre-flight banner + `shared_deps_synced`/`shared_deps_drift` in previz.json provenance | visible, non-blocking |
| Git hook | BOTH repos `.githooks/pre-commit` (tracked shim + `core.hooksPath`; install.sh + `--install-hooks` wire it) | OWNER-AWARE: blocks unmarked non-owner commits (`PORTBACK_PENDING` marker); the owner's own edits pass (s34 fixed the s33 hook that blocked them too) |

## The tool (`tools/sync_shared.py`, stdlib-only, dual-mode)

| Mode | Command | What it does |
|---|---|---|
| Emit | `--emit` | hash all entries, import-closure AST check (no half-shipped packages), owner-missing check, write manifest + audit |
| Check | `--check [--repo DIR]` | classify every entry (truth table below); works in single-repo sessions via the vendored record |
| Sync | `--to DIR [--include-new] [--force] [--install-hooks]` | guarded owner→consumer copy; first sync needs `--bootstrap` |
| Adopt | `--adopt FILE...` | record refresh for an informal sync (bytes came from the owner; refuses on true divergence) |
| Pre-commit | `--pre-commit` | the owner-aware gate the `.githooks/pre-commit` shim execs (s34: the logic rides the manifest-synced tool, so hook fixes propagate via the sync; the shim is 12 identical lines in both repos) |

In consumers the tool runs as the vendored `scripts/check_shared_sync.py`
(check + adopt + pre-commit — no kit needed; the vendored copy is refreshed
by every `--to`).

### The classification truth table

C = consumer file sha, R = consumer record sha, O = owner file sha:

| State | Meaning | Action |
|---|---|---|
| IN-SYNC | everything matches | none |
| OWNER-AHEAD | the owner moved | run `--to` FROM THE KIT |
| NON-OWNER-AHEAD | the consumer edited a governed file | port back to the owner |
| RECORD-STALE | consumer bytes == owner's, record is old | `--adopt` |
| DIVERGED | both changed | manual merge |
| NOT-SYNCED / OWNER-MISSING | bookkeeping mismatch | `--include-new` / manifest edit |

In single-repo sessions O is unobservable: RECORD-STALE and
NON-OWNER-AHEAD print BOTH remedies.

### The three-way guard

`--to` overwrites a consumer file ONLY if its sha == the consumer's
record sha (last-synced state) or == the incoming owner bytes
(already synced informally). Anything else → REFUSE ("non-owner
ahead — port back first or --force"). A hand-edited record is caught
by the state-file integrity check (the record must be consistent with
the canonical manifest).

## The tier-B re-baseline duty (s34 audit S4 — a cross-repo law)

`previz.json`'s `crowd.code_sha` is the git TREE HASH of previz's
`scripts/crowd_v6/`. ANY commit touching that directory changes the tree
hash and breaks the kit's tier-B byte-pin BY DESIGN
(`tests/test_export_previz_package.py` B2 — the pin includes code_sha).
The duty: **whoever moves `scripts/crowd_v6/` re-runs the kit's tier-B
the same session and re-baselines consciously when the delta is exactly
the tree pin** (payload-verified byte-identical modulo code_sha), with
the re-baseline commit explaining why. The r058-r059 previz folds sat
kit-tier-B-broken for a day because no doc named this duty.

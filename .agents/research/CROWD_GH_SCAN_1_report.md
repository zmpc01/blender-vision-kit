# CROWD-GH-SCAN-1 — Comprehensive GitHub API Scan for Crowd Simulation OSS Repos

**Task ID:** CROWD-GH-SCAN-1
**Method:** GitHub REST v3 search API, 20 queries, PAT-authenticated, 5000 req/hr core + 30 req/min search budget.
**Scope:** Exhaustive scan to satisfy user brief "leave no stones unturned"; complements (does not replace) CROWD-RESEARCH-EXT-1's curated 10-repo survey.

## 1. Executive summary (5 bullets)

- **Coverage:** 20 search queries → 1,053 unique repos after dedupe → 398 passed relevance filter (score ≥ 3) → README-verified 59 priority candidates → **45 repos in final table**. Queries with productive yield (≥20 relevant results): `crowd simulation` (1014 total), `crowd python` (1354), `crowd sim` (912), `steering behaviors` (871), `pedestrian simulation` (437). Low-yield queries: `agent navigation blender` (1), `navmesh blender` (7), `crowd navmesh` (8) — the Blender-crowd niche is genuinely sparse on GitHub.
- **Python ORCA / RVO2 implementations exist that CROWD-RESEARCH-EXT-1 missed.** The canonical `sybrenstuvel/Python-RVO2` (242★, Apache-2.0, Cython over UNC's RVO2 C++) was referenced obliquely via its 14★ `mit-acl` fork in the prior report; the 242★ canonical repo was not cited. Two pure-Python impls also exist: `Muon/pyorca` (36★, MIT, pedagogical, 2D only) and `chengji253/RVO2-python` (65★, MIT, 2026-01). **Any one of these could spare the kit from writing its own ORCA solver for v1.2.**
- **Top 3 NEW discoveries** (not in CROWD-RESEARCH-EXT-1):
  1. `andriyDev/dodgy` (37★, Rust MIT/Apache, 2026-03) — Rust ORCA crate in 2D and 3D, mirroring `snape/RVO2` API; directly absorbable as PyO3 wheel if the kit follows the bgyss/Blender-Crowd Rust-core pattern.
  2. `isaac-mason/navcat` (293★, TS/JS MIT, 2026-09) — pure-JavaScript recast-equivalent (no WASM, no C++ compile); same author as the WASM-based `recast-navigation-js`. Reference architecture for "what if we did navmesh in pure Python."
  3. `innocentmiau/MiHordeTraffic` (0★, C#/Unity MIT, 2026-09-12) — flow-field crowd pathfinding with congestion-aware routing, 5000 agents at 12ms median frame. Validates that flow fields beat NavMeshAgent at scale and that **congestion-aware cost-weighting** is the key new idea beyond Treuille 2006.
- **Top 3 ABSORB candidates:** (a) `sybrenstuvel/Python-RVO2` for ORCA, (b) `andriyDev/dodgy` (Rust ORCA, dual-license MIT/Apache — no GPL contamination) if the kit goes Rust-core like bgyss, (c) `ikpil/DotRecast`'s `DetourCrowd` C# implementation as the algorithmic reference for the kit's own NumPy port of crowd manager + ORCA tile-local-avoidance (recastnavigation upstream's DetourCrowd is the most production-proven crowd manager code in OSS).
- **Algorithmic landscape shift vs CROWD-RESEARCH-EXT-1:** the prior report cataloged 15 algorithms; this scan adds 4+ more active research lines: **Position-Based crowds** (Weiss 2019; 3 repos including kit's own `crowd_fields.relax`), **Physics-infused ML (PIML)** (KDD'22), **CADRL/DRL collision avoidance** (yufengzhe1, kayuksel), **Congestion-aware flow fields** (MiHordeTraffic), and **Continuum Crowds GPU impls** (hduregger/crowd OpenCL). All absent from the prior 15-algorithm catalog.

## 2. Methodology

PAT-authenticated GitHub REST v3 search endpoint (`/search/repositories?sort=stars&order=desc&per_page=100`). 20 queries covering: general (`crowd simulation`, `crowd sim`), algorithm-specific (`ORCA avoidance`, `RVO avoidance`, `boids steering`, `steering behaviors`, `recast detour`, `crowd navmesh`), domain-specific (`pedestrian simulation`, `pedestrian dynamics`), language-specific (`crowd python`, `crowd numpy`, `crowd rust`), Blender-specific (`crowd blender`, `navmesh blender`, `agent navigation blender`), and animation-adjacent (`motion synthesis character`, `locomotion animation`, `agent steering python`). Page 1 (top 100 by stars) fetched for all 20 queries; auto-queue for page 2+ if last item on page 1 had > 5 stars — **no query hit that threshold**, so single-page coverage was sufficient. The search rate limit (30 req/min) was respected with 2.2s sleep between calls. Total search calls: 20 (1 per query). Total core API calls for README + metadata: ~120. After dedupe (1,053 unique repos), relevance-filtered via keyword regex scoring (positive: `crowd sim`, `navmesh`, `recast`, `ORCA`, `RVO`, `pedestrian dynamic`, etc.; negative: `crowdfund`, `crowdsource`, `crowd counter`, `crowdhuman dataset`). 398 repos scored ≥ 3; 59 of these (highest stars per tier) had README fetched and manually verified. Cross-checked against the prior CROWD-RESEARCH-EXT-1 source list (bgyss, CrowdMaster, Recast/Detour, RVO2, Python-RVO2 mit-acl fork, OpenSteer, SteerSuite, JuPedSim, Menge, Golaem) to mark NEW discoveries.

## 4. Top 10 NEW discoveries (not in CROWD-RESEARCH-EXT-1)

1. **`sybrenstuvel/Python-RVO2` (242★, Apache-2.0, 2024-05).** Cython bindings to snape/RVO2 C++; `PyRVOSimulator.doStep()` releases GIL. **The canonical Python ORCA binding** — EXT-1 cited only the 14★ `mit-acl/Python-RVO2` fork. Pip-installable (needs CMake + Cython at build). Kit: spike build in 4GB container; if green, this is v1.2 ORCA backend. Fallback: `Muon/pyorca` for a NumPy port.
2. **`andriyDev/dodgy` (37★, MIT/Apache, 2026-03).** Rust ORCA crate (`dodgy_2d` + `dodgy_3d`); `Agent::compute_avoiding_velocity(neighbours, pref_vel, max_speed, dt, &AvoidanceOptions)`. Ported from RVO2-3D's `Agent.cc`; uses `glam::Vec3`. **Direct bgyss/Blender-Crowd pattern fit** — strongest ABSORB candidate if orchestrator commits to a Rust core. Permissive dual-license = no GPL contamination (unlike bgyss).
3. **`isaac-mason/navcat` (293★, MIT, 2026-09).** Pure-JS navmesh construction + querying (no WASM, no C++ build); same author as `recast-navigation-js`. Single + multi-tile; JSON-serializable. Proves a pure-Python navmesh is feasible; useful algorithmic reference for the kit's planned Blender-native navmesh (design v1.1 §6.1) — borrow navcat's data structures.
4. **`innocentmiau/MiHordeTraffic` (0★, C#/Unity, MIT, 2026-09-12).** Flow field + **congestion-aware routing** — cell cost priced by measured crossing speed, so jammed routes become expensive and the crowd reroutes. 5000 agents @ 12ms median, 16ms p95 — beats Unity NavMeshAgent by ~35%. Burst-jobified separation with spatial hash. **Algorithmic novelty worth porting** to the kit's deferred flow-field milestone.
5. **`Muon/pyorca` (36★, MIT, 2021-01).** Pure-Python ORCA in two files (`pyorca.py` + `halfplaneintersect.py`) with pedagogical comments. 2D only, 3D LP fallback is a TODO. **Algorithm reference for the kit's planned NumPy ORCA** (design v1.1 §6.3) — read once, port LP fallback to NumPy, kit has a self-contained no-C-dep ORCA.
6. **`chengji253/RVO2-python` (65★, MIT, 2026-01).** Newer pure-Python ORCA, strictly following official C++ logic. Useful as **correctness oracle** when validating the kit's NumPy ORCA — run same scenarios through both, compare agent trajectories bit-for-bit. Less pedagogical than pyorca but more complete.
7. **`ikpil/DotRecast` (944★, Zlib, 2026-09).** Most-starred Recast port (C#); includes `DotRecast.Detour.Crowd`. C# reads like executable pseudocode; **the kit's NumPy port of DetourCrowd should reference this** instead of the macro-heavy C++ upstream. NuGet-published; CodeQL + CI gates.
8. **`tsinghua-fib-lab/PIML` (20★, MIT, 2024-04).** Physics-infused ML for Crowd Simulation (KDD'22). ## 6. Cross-cutting findings

- **Algorithmic patterns:** **ORCA is overwhelmingly the de-facto standard** for local avoidance — 8+ ports across C++/C#/Java/TS/Go/Rust/Python (snape/*, ikpil, recast4j, kylin206, palmerabollo, downflux, andriyDev, Muon, chengji253, sybrenstuvel). **Context Steering (Fray 2013/2015)** has only 1 prominent OSS impl (`RubenFrans/ContextSteering-Unity`, 59★) — much-discussed, not widely implemented. **Social Force Model** has 4 Python + 1 Java impl. **Boids**: many demos, no library winner; `libgdx/gdx-ai` (Java) is the most complete (steering + formation + A* + HPA* + FSM + BT in one framework). **Continuum Crowds (Treuille 2006)** has 1 active impl (`hduregger/crowd`, 2011, OpenCL) — minimal OSS footprint. **Flow fields** have `vonWolfehaus/flow-field` (JS, 2016) + `innocentmiau/MiHordeTraffic` (Unity, 2026, with congestion-aware pricing — a genuine algorithmic extension beyond Treuille 2006). **Position-Based crowds (Weiss 2019)** has 2 impls; kit's own `crowd_fields.relax` is essentially this algorithm. **Learned policies** (CADRL/PIML) — 3 impls, emerging research line, not production-ready.
- **Language dominance:** **C++ leads** at algorithmic-library tier (snape/RVO2, recastnavigation, OpenSteer, Menge, SteerSuite, pedsim, tomerwei, hduregger). **C# dominates Unity-bound ports** (DotRecast, RVO2-CS, RVO2-Unity, UniRecast). **Python is binding/scripting tier** (Python-RVO2, pyorca, RVO2-python, jupedsim, PedPy, crowddynamics, ERVO, PIML, group-social-force). **Rust emerging** (dodgy, divert, orhanbalci/rust-steering-behaviors) — small star counts but permissively licensed and bgyss demonstrates the pattern works. **TypeScript/JS** is the web-demo tier. **Go** has only `downflux/go-orca` (49★, abandoned 2022).
- **NEW algorithms not in EXT-1's 15-entry catalog:** (a) **Position-Based crowds (Weiss 2019)** — 3 impls; (b) **Physics-infused ML (PIML, KDD'22)** — hybrid SFM + learned corrections; (c) **CADRL/DRL collision avoidance** (Chen 2017, Everrett 2018) — trained on ORCA; (d) **Congestion-aware flow fields** (`innocentmiau/MiHordeTraffic`) — dynamic cell pricing by measured crossing speed, not in Treuille 2006 or any survey paper seen; (e) **Floor Field CA (Burstedde 2001)** — `chraibi/cellular_automata`, microscopic ped dynamics alternative to force-based; (f) **Extended RVO (ERVO)** — sensor-augmented ORCA for robot nav (IROS 2020).
- **Blender-specific crowd add-ons missed in EXT-1:** **11 new repos** (vs EXT-1's 4: bgyss, CrowdMaster, iCrowds, Agents-GN). Most notable: `navaselmon/crowdmixer-ce` (2026-07, CE bugtracker-only; closed-source commercial core on Superhive; GN-based; Standing/Flow Curve/Stadium crowd types); `cjhosken/crowd_manager` (6★, 2022, GPL, abandoned, node-based); `alice-bian/crowd-diversity-pipeline` (2026-07, **not Blender-crowd-sim but Blender→UE5 USD asset pipeline** for crowd diversity, Sony KPDH previs-style — highly relevant as inspiration for kit's previz goal); `tangent-animation/crowd_tools` (0★, 2017, Tangent Animation studio internal, no license); `globglob3D/agents_documentation` (docs-only for an "Agents" GN add-on, parent not found); `DannySortino/Project` (2025-07, amateur script-paste); `Peter-Noble/InAIte` (5★, 2016, abandoned); `NeugTV/Blender-Crowd-System` (0★, 2026-02, empty README). **Net finding:** the Blender-crowd-sim OSS ecosystem is *genuinely sparse*. bgyss/Blender-Crowd is by far the most serious OSS project; everything else is abandoned, amateur, closed-source-commercial, or tangential. **The kit's planned crowd system has minimal OSS competition in the Blender-specific niche.**

- **Python ORCA implementations that save the kit from writing its own:** **4 options exist**, ranked by maturity for kit adoption:
  1. `sybrenstuvel/Python-RVO2` (242★, Apache-2.0, Cython over C++ RVO2) — most production-ready; **first-choice if build succeeds in 4GB container**.
  2. `chengji253/RVO2-python` (65★, MIT, pure Python, 2026-01) — recent, strictly follows official C++; correctness oracle.

  4. `denkiwakame/Python-ERVO` (24★, Apache-2.0, Cython over Python-RVO2) — sensor-augmented extension (IROS 2020).
